# pi-telegram-gateway

[English / 完整配置与安全说明](README.md) · MIT · Node.js ≥ 22.19

通过 Telegram 私聊话题管理多个持久化 pi session。独立常驻网关，使用 pi SDK，不要求终端一直开着。参考 Hermes 的 `/topic` 与 `dm_topic_auto_transfer` 行为，不是 Hermes 分支，也不是完整功能复刻。

## 当前状态

**0.6.2 早期版本**：路由、按钮选择器及真实 SDK 会话/模型/推理设置持久化测试已通过；已实测标题模型请求、真实 Telegram 改名 API 与 SDK 名称同步。**完整对话/工具流程尚未全部验收，当前客户端的原生改名事件仍不可靠**。未发布 npm，请从源码安装。

## 安装

```sh
git clone https://github.com/bqingx/pi-telegram-gateway.git
cd pi-telegram-gateway
npm ci
npm link
pi-telegram-gateway init
```

1. 先配置 pi 模型及登录凭据，默认使用 `~/.pi/agent`（可用 `PI_CODING_AGENT_DIR` 指定）。
2. BotFather **Mini App → My bots → 你的 bot → Bot Settings → Threads Settings** 开启 **Threaded Mode**；需要手动创建话题时，也允许用户建话题。
3. 编辑 `~/.config/pi-telegram-gateway/config.json`：`allowedUsers` 填自己的 Telegram **数字用户 ID**，`cwd` 填工作目录，其他路径也使用绝对路径。
4. 本地编辑 `tokenFile` 指向的文件，写入 Bot Token，设置 `chmod 600`。不要将 Token 写进命令参数、代码或仓库。
5. `pi-telegram-gateway start`。可通过 `PI_TELEGRAM_CONFIG` 指定配置文件。

空白名单拒绝启动；同一个 bot 不可同时运行其他轮询网关。已有 webhook 时拒绝启动，不会擅自删除。无需开放公网端口。

## 使用

- **根私聊 / General 发普通消息**：自动创建新话题、新 session，首条消息送入该 session，回复在新话题中。
- **话题内发消息**：继续绑定的 session；未绑定的话题自动分配新 session。
- **根私聊发命令**：不创建话题。
- `/topic`：查看当前绑定；在根私聊中显示会话列表。
- `/topic <session-id>`：切换到同用户、同聊天的旧会话，重放最近一条助手文本。
- `/sessions [页码]`：查看自己的会话，每页 10 条。
- `/new`：当前话题开启新会话，旧会话保留。
- `/status`：会话及运行状态。
- `/stop`：中止本话题任务，**不会撤销已经执行的工具操作**。
- `/menu`：当前模型、推理强度及设置按钮。
- `/language`、`/lang`：通过按钮选择中文或英文界面，无需绑定会话。
- `/name [新名称]`：同时改话题和会话名称；不带参数会弹出回复输入框。
- `/model`、`/models`：提供商 → 分页模型列表 → 确认切换，无需输入模型 ID。
- `/thinking`、`/reasoning`：点击选择当前模型支持的推理强度。
- `/help`：帮助；已绑定会话时同时显示设置按钮。

启动时自动注册 Telegram **内置命令菜单**，可直接点击菜单里的“会话设置 / 选择模型 / 推理强度”，再用消息内按钮操作，不需要手打完整命令或选项。未绑定会话的话题请先发消息或使用 `/new`。

模型列表只包含 pi SDK 当前有凭据可用的模型（包括已配置的兼容端点），带分页、返回、关闭及当前选中标记。切换前显示确认页、可用的目录价格估算及上下文将发送给所选提供商的提醒；价格不是最终账单保证，切换本身不发送模型请求。

推理选项直接读取 SDK 的支持列表，非推理模型会明确提示不可调节。切换模型可能自动重置/收窄推理强度，确认消息显示实际值。修改**仅作用于当前 session**，保存到会话文件，不改全局默认设置或其他话题，尚未发过消息的空会话也能恢复。已保存模型不可用时拒绝静默回退，请先修复本机 pi 模型配置/凭据。

按钮绑定发起用户、聊天、话题、消息及 session；10 分钟后、提交新消息、切换会话或网关重启后失效。其他用户、旧页面或已变化的设置不能通过旧按钮误操作；忙碌中禁止切换。

一个 session 不能同时绑定两个话题；可先在原话题 `/new`，释放旧绑定。运行中的会话禁止切换；忙碌时新消息明确拒绝、不排队。不同话题可以并行，默认最多 4 个，但共享工作目录与系统账户，**并非文件系统隔离**。默认不导入本机 CLI 会话；可按下文开启共享模式。

接受普通文本消息后立即显示 **正在输入**，pi 初始化、推理及执行工具期间每 4 秒刷新。根私聊建话题后会把状态切换到新话题；完成、失败、`/stop`、退出时停止刷新并取消未完成的状态请求。Telegram 没有显式停止输入 API，状态会在回复送达或约 5 秒后自然消失。状态请求采用短超时、失败冷却及限流退避，不阻塞或重试模型任务；话题输入状态被 API 400 拒绝时，参考 Hermes 回退显示在私聊中。它是尽力提供的任务活动提示，不是永久在线标志。

根私聊的普通消息会先通过所选模型生成不超过 24 个字符的简短标题，**再用该标题创建话题并命名原生 pi session**，因此客户端首次看到的名字就是最终标题（Telegram 私聊话题的后续改名会被旧客户端忽略，见下文）。`/new` 同样在收到第一条消息后生成。标题请求独立、无工具，仅使用经常见凭据脱敏后的首条消息（最多 2000 字符），输出上限 128 个词元、约 6 秒超时；返回的用量记入会话 `title` 用量记录。每个新会话因此会多一次短模型请求，可能消耗费用或订阅额度，并不默认免费。标题请求不进入正常聊天历史，也不执行工具。失败或空结果使用本地短标题回退；名称同步失败会显式提示，不重复执行用户指令。旧会话不自动追溯改名。

**需要可靠同步时，请使用机器人内的重命名入口：** 在 `/menu` 点“重命名话题与会话”，或从命令菜单选 `/name`，回复输入框输入 1–128 字的新名称。直接发送 `/name 新名称` 会立即修改两边，不再弹出输入框；旧 `/rename` 命令已停用。机器人在同一会话独占锁内调用 Telegram 改名 API、修改原生会话名称并显式确认，不调用模型。本机占用时同时排队，释放后再改两边；回复 `/cancel` 可取消。过期、重启或切换会话后的旧输入框回复会被拒绝，不会误发给模型。同名的 `TOPIC_NOT_MODIFIED` 按幂等成功处理；永久拒绝不会虚假改会话名称或无限重试。已用临时话题实测真实 Telegram API 与真实 SDK 名称一致，临时话题已删除。

**已知 Telegram 客户端缺陷（机器人端无法修复）：** 私聊话题通过 `editForumTopic` 改名后，服务器已保存，但已打开的客户端会继续显示旧标题；新建的会话/重新登录的客户端能看到新名称。官方 Bot API 维护者已在 [tdlib/telegram-bot-api#915](https://github.com/tdlib/telegram-bot-api/issues/915) 确认“只能等客户端更新修复，机器人端无法修复”，Hermes 用户也在同一 issue 复现。因此本网关对新建话题采用“先定标题再建话题”避开该问题；对已有话题的 `/name` 仍会正确写入服务器（`/status` 显示新名称），但客户端可能仍显示旧标题。

**当前私聊客户端直接改名的自动同步尚不可用，不能依赖它立即同步。** 真实排查中收到了用户 `/status`，却没有独立改名事件；此前模拟事件测试不代表原生客户端实测通过。监听只在 Telegram 确实投递名称元数据时尽力处理，官方 Bot API 也没有可直接读取话题名称的查询接口，不能凭空推断新名称。 网关同时订阅普通消息与 `edited_message`，处理 `forum_topic_edited` 及编辑后的私聊话题创建头；仅对本机器人在白名单用户私聊中的服务头放行机器人作者，普通文本编辑不触发模型。收到用户**修改已绑定话题名称**的元数据后，会话名称同步，并明确回复“会话名称已同步为：xxx”。手动名称不受自动标题 24 字限制，也优先于尚未完成的自动命名。改名仅更新元数据，不调用模型。会话被本机占用时先持久化待同步名称，显式提示“尚未同步”，每 2 秒检查一次，释放后自动同步最新名称并确认。网关重启可以继续处理待同步元数据，不重放聊天指令或工具；会话不再绑定原话题时丢弃该旧改名请求。机器人自身改名回声、仅图标变化、未绑定或无权限的话题事件不触发同步；本机改名暂不反向同步 Telegram。

只转发最终助手文本，长消息自动分段，不转发思考、工具日志和原始异常。不支持图片、语音、文件、流式编辑及任意 pi 终端交互命令。SDK 默认加载工作目录指令、技能、扩展，但不自动安装 CLI 特有的 MCP/codemode 内置扩展。

## 界面语言

Telegram 网关界面**默认中文**，不跟随 Telegram 客户端语言自动切换。直接点命令菜单中的“切换语言”，或在会话设置里点“语言”，选择 **中文 / English** 即可。根私聊、未绑定话题和任务运行期间都能操作，不调用模型、不修改模型或推理设置。

偏好按 Telegram 数字用户 ID 保存到 `state.json` 的 `languages`，同用户所有话题共用，重启仍有效。帮助、命令菜单说明、会话/占用状态、模型/推理按钮、确认、错误及重启提示均使用所选语言。Telegram 命令菜单按私聊单独覆盖，不影响其他用户；菜单更新失败时保留已保存偏好，并提示重新选择重试。切换后旧设置按钮失效，请重新打开菜单。

命令本名（Telegram 要求拉丁字母）、模型/提供商 ID、用户内容、已有会话标题和模型实际回复保持原样，不会自动翻译或改写历史。之前已发送的旧消息不回改，新打开的菜单和后续提示使用新语言。

## Telegram / 本机会话共享（可选）

配置 `sharedSessionOwner` 为**一个已在白名单中的 Telegram 数字用户 ID**，重启网关。这个用户的 `/sessions` 会发现当前 pi profile 中的本机会话，显示占用和接管状态；其他 Telegram 用户看不到这些本机历史。这是向指定用户开放本机聊天历史的明确授权。

共享的是**原始同一个 JSONL 文件与原工作目录**，不是复制。每次 Telegram 操作都重新加载，能读到本机最新历史、模型和推理设置。新建 Telegram 会话写入 pi 原生会话目录；旧网关会话保留原路径，也能通过 `pi-shared` 访问。

本机必须改用随包提供的受控入口：

```sh
pi-shared --list
# 首次：先关闭所有使用该会话的普通 pi 窗口，再明确接管并打开
pi-shared --enroll <session-id>
# 之后正常打开
pi-shared --session <session-id>
pi-shared --new
pi-shared                         # 交互式选择
```

既有普通 pi 会话会列为 **unmanaged**。在明确接管前，Telegram **拒绝打开它**，避免抢走本机正在使用、尚未加锁的会话。共享模式新建的 Telegram 会话自动纳入管理。接管命令代表你已确认没有普通 pi 窗口继续写这个文件；程序无法可靠检测所有不遵守锁的旧进程。

**互斥，不是实时镜像：** 本机启动器在启动 pi **之前**取得文件旁的独占锁，整个窗口存活期间占用，闲置也不释放；退出后才能给 Telegram 用。可在本机执行 `/shared-release`，等待当前任务结束并退出。本机受控窗口中的 `/resume`、`/new`、`/fork`、`/clone` 会被拦截，请退出后从 `pi-shared` 切换或新建；同会话 `/reload` 可用。要求本机 pi CLI 与当前固定 SDK 1.5.0 兼容。

Telegram 在读取/迁移会话前取得同一把锁，持续到本次 SDK 操作结束。生成回复、执行工具、恢复会话或改设置期间，本机打开会失败。Telegram 空闲后本机可以接手，即使话题仍绑定着它；本机窗口存活时 Telegram 新消息和设置操作明确拒绝，不排队、不强抢、不自动重试。本机退出后，下一次 Telegram 操作读取最新文件。不同 session 仍可并行。

**这是协作锁，不是系统沙箱。** 普通 `pi`、禁用/绕开扩展、直接改 JSONL、硬链接别名、手动删除活锁都可能绕过保护。无法诚实地保证“不遵守锁的原生进程”也会被阻止；所有共享会话的本机操作必须走 `pi-shared`。当前普通 pi 窗口不会自动获得保护。

会话旁保存 `.pi-shared.json` 接管标记及 `.pi-shared-lock/owner.json` 占用信息。崩溃不自动抢锁：先核对记录的主机、父进程、子进程及其他使用者，确认全部结束后才可手动清理死锁。缺少或异常占用记录同样拒绝接管。

## 持久化及故障

`dataDir/state.json` 保存 bot 身份、话题绑定、所属用户、轮询 offset 和最近任务状态；`dataDir/sessions/` 保存旧版/私有 pi JSONL 会话；共享模式还会引用 pi 原生目录中的原文件。状态、所有引用的会话文件和接管标记应一起备份，文件可能包含敏感工具输出。

为了避免崩溃后重复执行交易等副作用，**先落盘更新接收位置，再处理消息**；不是严格恰好一次执行。崩溃可能丢失已接收但未完成的任务、留下空话题或部分操作，不会自动重放指令。重启时尽力通知中断任务。回复发送失败可能部分送达，可以绑定同一 session 重放最后文本，不要盲目重复交易指令。

离线期间尚未接收的 Telegram 消息会在启动后处理；发送时效性指令时要注意。建话题失败直接报错，不会串到其他话题。

独占锁为 `dataDir/gateway.lock`。正常退出自动释放；强制崩溃后须检查其中 `pid`，确认没有活跃进程，才能手动删除。不得删除仍在运行的锁；不同服务器间无法靠此锁检测重复 bot。

## 安全边界

**白名单用户可以通过 pi 使用网关系统账户的权限**，包括 shell、文件、网络以及本地配置的钱包工具。白名单不是沙箱、交易审核或额度限制。只添加完全信任的人；分享部署时使用独立非 root 用户、受限容器/工作目录/模型配置。Telegram bot 聊天不是端到端加密。

不接收群聊、编辑消息及 bot 消息；陌生用户不会自动注册。程序不主动输出 Token URL、内部工具日志及原始异常，但模型回复本身仍可能泄露敏感内容。金融类工具应另外配置并验证无界面的严格权限策略，网关本身不提供钱包授权政策。

### 可选事件诊断

私密网关配置中加入 `"diagnostics": true` 并重启，可记录事件/消息的**字段名**、更新/消息/话题 ID、发送者与机器人标志、话题名称**长度**。不记录正文、标题内容、回调数据、凭据或原始 API 错误，默认关闭。出现嵌套回复话题头时，也只记字段名及标题长度。用于核实客户端改名究竟被投递成服务消息、编辑后的话题头，还是没有投递。若 Bot API 没有提供名称元数据，不能仅凭更新序号猜出新标题；模拟事件测试通过不等于真实收件已验收。
